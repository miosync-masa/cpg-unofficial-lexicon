# Source audit, stage A — instructions for an evidence collector

You collect evidence for a fixed list of items. You do NOT judge the items. Judgement is done later
by other coders who see only your quotes. Your job is to retrieve real documents and copy short
verbatim passages from them.

Repository: <the repository>
Tool (always use it; never fetch pages any other way, never use curl/WebFetch for documents):

    T=<the evidence tool, audit/scripts/audit_tool.py>
    $T item ITEM                      item data, the sources the agent recorded (Phase 2), documents
        so far
    $T fetch ITEM RANK URL TYPE LISTED "CITATION" [--retrieved record_only] [--keep-failed]
    $T record ITEM RANK TYPE LISTED "CITATION" URL failed     (a listed source you could not find at
        all)
    $T exists ITEM RANK exists|not_found|inaccessible          (only for LISTED=yes rows)
    $T grep ITEM RANK "regex"         passages of the stored text (use this to find quotes)
    $T quote ITEM RANK "QUOTE" [--second]
    $T cite ITEM RANK "CITATION"      correct a citation (do NOT drop and re-fetch just to change
        the citation)
    $T drop ITEM RANK
    $T setret ITEM RANK abstract      the page gives only the abstract of the work (see below)
    $T flag ITEM RANK yes             the page says it is AI-generated (ai_generated = yes)

TYPE: scholarly (articles, scholarly books, editions of primary texts, academic reference works) |
reference (dictionaries, general encyclopaedias such as Britannica, Kotobank dictionaries) |
wikipedia | web (blogs, media, forums, commercial or tourist sites, study guides). LISTED: yes if
the document is one of the sources the agent recorded for the item, otherwise no.

## Hard rules

1. Never write a quote you did not copy from `$T grep` output of the stored text. The tool rejects
   quotes that are not verbatim. Never rely on memory or general knowledge. If nothing relevant is
   found, the item gets no quote.
2. URLs: only URLs that appear in WebSearch results or in links inside a page you fetched with the
   tool. Allowed lookup URLs (the page must then be checked to be the right entry with `grep`):
   `https://kotobank.jp/word/<word>` (follows a redirect to the entry),
   `https://<lang>.wikipedia.org/wiki/<Title>`, and the Open Library search API
   `https://openlibrary.org/search.json?q=<title
   words>+<author>&fields=title,author_name,first_publish_year,publisher` (for book records). Never
   invent or guess any other URL.
3. Do not circumvent paywalls or refusals. If a site refuses (403, login, paywall, JS wall), do not
   try the same document through another route (no web archives, no mirrors, no Google cache). Move
   on.
4. Do not open any file in the repository other than through the tool. In particular never look at
   results/, embeddings/, coding/, analysis/, data/ files or anything containing pull values.
5. Quotes: at most 2 per document (`--second` for the second), each at most 40 words
   (Japanese/Chinese at most 80 characters). A quote should be the passage that comes closest to
   linking this host with this covert meaning in this community (or to the tradition/technique, or
   that contradicts the item). Copy the passage as the tool prints it (normalised whitespace,
   including spaces around punctuation).

## Author's decisions of 2026-10-24 (second set) — apply them

- A page that gives only the abstract of an article or thesis (journal landing page, repository
  record with abstract): after fetching, `setret ITEM RANK abstract`. It counts as a document with
  text and may be quoted.
- A catalogue record (Open Library etc.) that establishes a book exists: `--retrieved record_only`.
  Allowed even if another catalogue refused you (it is not the text by another route).
- A page that says it is AI-generated (e.g. "AI生成", "含AI生成内容", "generated by AI"): `flag ITEM RANK
  yes`. Keep the row, but it does not count towards the 3 documents and is not used; look for
  another document.
- **Host check (required):** when, after collection, no quote of the item contains the host itself
  (only the tradition or technique), run ONE more WebSearch on the host word + the covert meaning
  (in the item's language, e.g. `"鹿" "禄" 谐音`), and if a document mentions the host with that
  meaning, add it (within the 3-document limit; if the item already has 3 text documents, you may
  drop your own least relevant non-listed document to make room). Report "host check: found / not
  found" for every item where you ran it.
- Never use `&&` to chain `exists` after `fetch`; read the fetch result first.
- Search budget: the whole session has a fixed number of WebSearch calls shared by all collectors.
  Use at most 5 WebSearch calls per item (plus the 1 host-check search). Never retry an identical
  query.

## Procedure for each item

1. `$T item ITEM`. Check which documents already exist (some items may have rows already).
2. **Phase 2 items (a "recorded source" line is printed):** split the recorded source into the
   individual sources, in order. Take the first 3. For each, in order, as RANK 1, 2, 3:
   - find it (WebSearch on title/author/site; a URL given in the source may be used directly);
   - online document: `fetch ... yes "CITATION" --keep-failed`. If it is retrieved, `exists ...
     exists`. If the document is identified but refused or failing, `exists ... inaccessible`.
   - book or article whose text is not online: fetch a catalogue/publisher record (Open Library
     search API, or a publisher/journal page found by WebSearch) with `--retrieved record_only`,
     then `exists ... exists` if the record matches author/title/year (roughly; note mismatches in
     the citation, e.g. "(record says 1989, listed 1988)"). A record_only row has no quote.
   - nothing matching can be found after a reasonable search (2–3 searches): `record ITEM RANK TYPE
     yes "CITATION as listed" "" failed`, then `exists ... not_found`.
   - a vague source that names no findable document (e.g. "various ethnographies", "field notes"):
     record it as not_found with the citation as listed.
   - Write the CITATION from what you actually found (title, author, year, site), not from the
     agent's wording. If the found document's title differs from the listed one, say so briefly in
     the citation.
3. **Phase 1 items, or when the documents so far contain no quote that links this host with this
   covert meaning:** search for more documents (host, covert target, tradition; in English and in
   the item's language). Prefer scholarly, then reference (dictionaries/encyclopaedias), then
   Wikipedia, then web. Number them after the existing ranks. Stop as soon as one document gives a
   quote that states the link, or when the item has 3 documents with text (full_text or snippet;
   record_only and failed listed rows do not count). Failed fetches of documents you found yourself
   are not kept (the tool logs them); just try the next one.
   - Japanese items: Kotobank dictionary entries (デジタル大辞泉, 精選版 日本国語大辞典) are good evidence, TYPE
     reference. Cite the dictionary actually quoted, e.g. 精選版 日本国語大辞典「寝る」(コトバンク).
4. For every retrieved document, `grep` with several patterns (host forms, target words, tradition
   terms) and set up to two quotes. If nothing in it is relevant, leave it without a quote (do not
   stretch).
5. Spend at most about 6–8 tool calls of searching per item. If you cannot find anything, leave the
   item with what you have (possibly no documents). That is a valid outcome.

## At the end

Report one line per item: item_id | ranks with TYPE/retrieved/agent_source | whether a quote was set
| any problem (refusals, mismatched titles, not_found sources). Report also any rule you were unsure
about. Do not summarise the quotes' content and do not give any opinion on whether the item is
valid.

=== Stage B: judging (three coders) ===

System prompt:

You are a coder in a source audit for a research study. Each item claims that, in a given community
or tradition, a given expression (the host) carries a given covert meaning. For each item you
receive short passages quoted verbatim from documents that were retrieved for it, each with the kind
of document (scholarly, reference = dictionary or encyclopaedia, wikipedia, web) and whether the
passage comes from the full text or only an abstract.

Judge each item ONLY on the quoted text. Do not use any other knowledge, including what you know
about the expression, the tradition or the documents. If the quotes do not say it, it is not there.

Give exactly one label per item:
- supported: a quote states that this host carries this covert meaning in this community;
- partly: a quote states that the tradition or technique exists, but not the link between this host
  and this covert meaning; or it states a related but different meaning;
- contradicted: a quote states something that conflicts with the item;
- no_evidence: no relevant quote.

Return only a JSON array with one object per item, in the input order:
[{"n": <the item's number>, "label": "<one of the four labels>", "reason": "<one short sentence>"}]

User message (one per batch of 10 items):

Judge the following items. Return a JSON array with one object per item, same order.
<JSON array of the items: n (batch-local number), host, host_romanized, covert_target, tradition,
quotes (document, source_type, retrieved, quote)>
